# Rubrics 编写方法

## 用途与读取时机

本文件是随 Explicit-Info-Doc 分发的独立方法参考。新建或实质修改 showcase 的通过标准、完整评测集的逐题 Rubrics 时读取；纯措辞精简可复用已核验的题目和依据，不必重复加载。无需安装或调用外部 `evaluation-rubrics`，也不声称已调用该 Skill。

输入为当前 Query、本期确认的能力与业务边界、统一环境说明、单题材料/初始状态，以及已确认的修改方向。标准用于判断被测模型本轮是否完成任务；题目价值、真实性、业务价值是选题质量要求，不写成模型得分条件。

## 从任务生成标准

1. **找必要结果**：明确目标对象、用户要完成的操作或判断、期望产物和必要条件。只纳入 Query 与本期业务边界支持的成功要求，数量、时序或格式仅在影响本题完成时保留，不新增隐藏任务或无依据门槛。
2. **对应可观察证据**：用返回内容、实际产物、对象状态或可核验结果判断是否达标。材料写客观事实和初态，判断线索须经本轮附件或本期工具实际获取；Rubrics 写预期结论及成功结果。缺少必需依据时补齐材料要求或改题，不能凭空写死答案，也不能用预期结论替代材料事实。
3. **写短且独立的要点**：每条用通俗短句表达必要考点，合并重叠项，覆盖全部必需条件。优先正向描述正确结果，只有影响成败的业务边界才保留必要负向要求；不堆泛化禁令、细碎要求或冗长过程。合理等价答案或实现方式可接受时写明判定范围，不固定无依据的唯一措辞、操作路径或调用次数。
4. **检查单轮与一致性**：Query、材料和标准指向同一对象、条件与结果。不要求展示模型内部推理，不依赖前轮聊天、用户中途补答或后续确认。信息不足边界题的终点限于本轮有依据的反馈，不能再要求用户回答后的执行结果。

## 计分与呈现

- 所列标准均为必需条件：全部满足得 **1**，任一不满足得 **0**。不采用部分得分、多级量表、权重、平均分或“达到一定比例即通过”。
- showcase 的“通过标准”使用原生无序列表，每条一个要点；完整评测集的 Rubrics 单元格按实际换行写 `R1: …`、`R2: …`。条数由任务需要决定，不固定为 4—8 条，也不为凑条数拆碎或重复要求。
- 不新增外显评分列、额外确认轮次、正式多人校准流程或评分一致率阈值。

## 内部复查

用一个满足全部必要条件的预期结果，以及一个违反关键条件的结果，检查同一组标准能否清楚地区分通过与不通过；若存在合理等价结果，再核对它不会被误判。遇到模糊、重复、漏项或材料不足，修订对应内容后复核。此为编写时的轻量语义检查，不是实际执行评测，不生成通过率或声称模型已验证成功。

## 方法来源与适配

方法来源为 `evaluation-rubrics` 的 `SKILL.md` 中 Checklist（Binary）模式，以及 `resources/template.md` 的目的界定、条件筛选和描述写法、`resources/methodology.md` 的可观察性、隐藏要求和重叠条件检查；此处已自行提炼为可独立使用的方法，无需访问原文件。

全部满足的 0/1 口径、单轮边界、简洁要点和两种呈现格式来自本项目用户已确认规则。原方法中的多级评分、权重、固定条数和正式校准要求未纳入；执行以当前项目规则为准，不把来源通用默认值重新引入。
